### 1. PC 端项目分组侧栏

- 侧栏收起 / 拖拽调宽（200–500px，双击恢复）、项目组折叠、底部工具栏（设置、帮助、定位当前会话、收起）。

### 1b. 侧栏改为"文件夹显式归属"（原待办 B2，2026-10-16 完成并上线）

- 大文件夹只是分组容器，只有名字，和路径无关；会话归属由用户决定（新建时所在文件夹、拖拽 chip 或整张卡片、右键"移到「X」/移出文件夹"），`cd` 不会换组。
- 文件夹不能直接删除，组头只有"重命名"和"在此新建会话"。最后一个会话离开时文件夹随之删除：本设备关闭时确认框内提示；拖出/移出时先确认；别处关闭或进程退出时自动删除并提示"已无会话，已删除"。
- 新建文件夹必须同时新建第一个会话，取消则都不建。
- 文件夹内按工作目录合并为目录卡片（子文件夹）。卡片可重命名（只改显示名，按文件夹分别记，改回原名即恢复默认）；整张卡片可拖到别的文件夹，目标已有相同目录时自动合并，名称以目标为准。
- 同一目录可以出现在不同文件夹；没有归属的会话在最后的"未分组"（灰色小字）；一个文件夹都没有时直接平铺。
- 顶部标签栏只显示当前文件夹里与当前会话同一目录的会话（按建议选了这一种，可改为显示当前文件夹全部会话）。
- 存储：`~/.terminal-web/projects.json`（文件名沿用），结构 `{ folders, members, dirNames }`；旧的路径式项目在首次读取时迁移为同名文件夹并立即写回。迁移前的原文件备份为 `projects.json.bak-before-folders`。
- 接口 `/api/folders`：`create` / `rename` / `move`（可带 `card` 携带卡片名）/ `renameDir`，不提供删除。会话列表接口每次刷新时清理已不存在会话的归属。
- 代码：`src/projects.ts`、`web/project-groups.ts`（`groupByFolder`、`wouldEmpty`）、`web/project-sidebar.ts`、`web/terminal.ts`；测试 `tests/project-groups.test.ts`。

### 2. 会话状态显示

- 状态由服务端统一判断（`src/agent-status.ts`），通过 SSE 推给浏览器，所有设备一致，没打开过的标签也有状态。
- 五种状态，标签、侧栏、手机端共用：等待确认（橙色闪烁）、执行中（转圈）、完成未读（亮绿 + 标签淡橙底）、完成已读（暗绿）、空闲（灰）。
- 正在看的会话自动已读（页面可见且有焦点、标签在屏幕上）；页面标题前显示需要处理的会话数。
- 状态来源三选一，在设置面板"状态来源"切换，立即生效、各设备共用（存 `~/.terminal-web/agent-status.json`）：
  - **钩子**（默认）：agent 通过钩子主动上报；没上报过的会话用屏幕识别兜底。
  - **屏幕识别**：服务端每秒读 tmux 屏幕，按各 agent 的精确字样判断。
  - **原始**：原来的浏览器端逻辑，代码原样保留。
- 钩子接口 `/api/agent-hook`，钩子脚本 `scripts/agent-hook.sh`，一键安装 `scripts/install-agent-hooks.mjs`（`--check` / `--uninstall` / `--only` / `--url` / `--claude-dir`）。
- 一键安装支持 Claude Code（自动识别 `~/.claude`、`$CLAUDE_CONFIG_DIR`、`~/.claude-*`）、Codex（`hooks.json` + `config.toml` 信任条目）、Kimi Code（`~/.kimi-code/config.toml` 的 `[[hooks]]`，7 个事件）、qwen-code（`~/.qwen/settings.json` 的 `hooks`，10 个事件，同 Claude）和 opencode 2（`cli.json` 里登记 TUI 插件，1 个入口）。
- 屏幕识别规则覆盖：Claude Code、Codex、qwen-code、Kimi Code、opencode、MiMo Code（字样对照表见部署指南第 8 节）。
- 本机已安装钩子：`~/.claude`、`~/.claude-relay`、`~/.codex`、`~/.kimi-code`、`~/.qwen`、`~/.config/opencode/cli.json`，原文件备份为 `*.bak-terminal-web`。
- 测试：`tests/agent-status.test.ts`、`tests/project-groups.test.ts`。

### 2b. Kimi Code 接入钩子（2026-10-21）

原先一键安装只覆盖 Claude Code 和 Codex，Kimi 靠屏幕识别；它的执行中状态行没有固定字样，圆点只能认出"按过一次 Esc"和"等待确认"，所以按待办 A 查清的格式补上了钩子。

- 配置：`~/.kimi-code/config.toml`（`$KIMI_CODE_HOME` 可改）的 `[[hooks]]`，每条只写 `event` / `command` / `timeout`（5 秒）。事件为 `UserPromptSubmit`、`PreToolUse`、`PostToolUse`、`PostToolUseFailure`、`PermissionRequest`、`Stop`、`StopFailure`。
- 安装器新增 `--only=kimi` 和 `Kimi Code n/7 hooks` 检查行；按行增删自己的 `[[hooks]]`，其余表格（包括 Orca 自己管理的 7 条）原样保留；首次修改前备份 `config.toml.bak-terminal-web`，重复执行不会重复追加。
- 卸载用 `--uninstall --only=kimi`，实测只删自己的 7 条，Orca 的 7 条和文件其他内容不变。

实测踩到的点：

- **不要写 `matcher`**：Kimi 把 matcher 当正则，Claude 的 `*` 不合法；而且它只认 `event` / `command` / `timeout`，多一个键整份配置就加载失败（不是忽略那一条）。
- **验证配置能否加载**用 `kimi provider list`：成功会输出 provider 列表和默认模型，配置有错会直接报错，不消耗模型额度。
- **服务只监听局域网地址时必须给 `--url`**：本机服务监听 `192.168.88.178:8090`，安装器默认探测的 `127.0.0.1:8090` 连不上，会显示 `server NOT reachable`；用 `--url=http://192.168.88.178:8090` 重跑即可，地址写进 `agent-hook.env` 后 Claude Code / Codex 的钩子也一起受益。
- **`--check` 不带 `--only` 时**，本机没装的 Claude Code / Codex 显示 0/N，退出码为 1，不代表 Kimi 有问题；检查 Kimi 用 `--check --only=kimi`。
- **上报依赖 `TMUX_PANE`（psmux 下还有 `PSMUX_SESSION`）**：psmux 每个会话的第一个 pane 都叫 `%1`，只带 pane id 会被服务端丢弃，所以钩子必须由 psmux 里的 agent 进程执行，才能继承这两个变量。
- **验证时不要在当前 Kimi 会话里直接跑钩子**：执行命令期间 pane 的前台进程是 bash，服务端会判成"agent 已退出"并立刻置为空闲，掩盖 `working`。正确做法是开一个临时 psmux 会话、跑非 shell 前台进程（如 `ping -t 127.0.0.1`），再手动喂事件；实测 `UserPromptSubmit` → `working`，`Stop` → `done`（未读）。
- **已运行的会话要重启**才加载钩子；新开的会话自动带上。

### 2c. opencode 接入插件（2026-10-21）

实现细节、安装和排查已单独整理到 [opencode 状态插件](opencode-状态插件.md)，下面只记决策和实测结论。

opencode 2 已经去掉了配置里的命令钩子，只有插件；而插件分两种进程：共享的 `opencode serve` 和每个会话的 TUI。共享服务进程的 `TMUX_PANE` 只记着"最先启动它的那个 pane"，多开 tab 时会报错会话，所以状态必须由 **TUI 插件**上报。

- 包结构：`scripts/opencode-status/`（`package.json` + `index.js` + `tui.js`），安装到 `~/.terminal-web/opencode-status/`。`package.json` 必须有 `exports["./tui"]`；**opencode 2.1.2 只加载"带 `./tui` 导出的包目录"，`cli.json` 里直接写一个 `.js`/`.mjs` 文件会被静默忽略**（`opencode plugin list` 里也看不到）。`index.js` 只是为了满足 opencode 的全局插件目录发现，服务端调用时直接 no-op。
- 注册：`~/.config/opencode/cli.json`（或 `$XDG_CONFIG_HOME/opencode/cli.json`）的 `plugins` 数组追加 `file:///…/.terminal-web/opencode-status`（目录 URL）。改完 cli.json 后运行中的 TUI 通常会自动热加载，没生效再重启。
- 状态判断不猜事件名：opencode 2 的事件族（`session.next.*` / `session.execution.*`）随版本变，插件每 400ms 读 `ctx.data.session.status(sessionID)`（`running` 或空闲）和 `permission.list` / `form.list`，按 `working → UserPromptSubmit`、`waiting → PermissionRequest`、`idle → Stop` 只在变化时上报。等待确认有 500ms 沉降，过滤掉被保存规则秒批的权限请求。
- 只跟随 TUI 当前显示的会话：在一个 pane 里切换 opencode 的会话时，圆点跟着切换后的会话走（terminal-web 的状态本来就是按 pane/tab 算的）。
- 安装器新增 `--only=opencode` 和 `opencode 1/1 plugin` 检查行；卸载用 `--uninstall --only=opencode`，会同时删掉 `cli.json` 里的条目和 `~/.terminal-web/opencode-status/`。opencode 1.x 没有这个插件接口，安装器跳过，继续用屏幕识别。
- 实测（opencode 2.1.2，两个 tmux pane 各跑一个 TUI）：发消息 `working`，question 工具弹出时 `waiting`，选完答案回到 `working`，结束后 `done`（未读），两个 pane 分别上报自己的 `%pane`，互不串。
- 测试：`tests/opencode-status.test.ts` 覆盖 `parseEnvText` / `computeState` / `transitionEvent`。

### 2d. qwen-code 接入钩子（2026-10-21）

qwen-code 的钩子是配置式、与 Claude Code 同构（`settings.json` 的 `hooks` 键、事件名一致、`{ matcher, hooks }` 结构一致、`matcher: "*"` 合法、用户级 command 钩子默认开启无需信任），照 Claude 的实现直接复用 `agent-hook.sh`。

- 配置：`~/.qwen/settings.json`（`$QWEN_HOME` 可改）的 `hooks` 键，10 个事件 `UserPromptSubmit`、`PreToolUse`、`PostToolUse`、`PostToolUseFailure`、`PermissionRequest`、`Notification`、`Stop`、`StopFailure`、`PostCompact`、`SessionEnd`，`matcher` 用 `*`，`timeout` 5 秒。`$QWEN_HOME` 解析照 qwen-code 自身的 `resolveQwenHome`：`~` 或 `~/…` 展开、其余按 cwd 解析。
- 安装器新增 `--only=qwen` 和 `qwen-code n/10 hooks` 检查行；`QWEN_EVENTS` 直接复用 `CLAUDE_EVENTS`（二者事件表一致）。默认检查跳过未安装的 qwen；显式 `--check --only=qwen` 仍要求安装完整。
- Claude/Codex/qwen 的刷新和卸载按单个 command 清理，混合组内的其他工具钩子及 matcher 保留；回归测试见 `tests/install-agent-hooks.test.ts`。
- 卸载用 `--uninstall --only=qwen`，只删自己的条目，`settings.json` 其余键（`ui`/`env`/`modelProviders` 等）原样保留；首次修改前备份 `settings.json.bak-terminal-web`，重复执行不会重复追加。

实测/核实踩到的点：

- **qwen 空输出即可**：`agent-hook.sh` 只对 `claude` 打印 `{}`（Claude 的权限钩子需要"无意见"之外的显式 `{}`）；qwen 的命令钩子退出码 0、stdout 为空即"无意见"，权限事件照样放行，无需改钩子脚本。
- **`timeout` 按秒**：qwen command 钩子 `timeout` 小于 1000 时按秒读（≥1000 才按毫秒），所以 `5` 就是 5 秒，沿用 Claude 的取值。
- **事件名/matcher 核对自 qwen 0.25.3 自带文档**（`lib/bundled/qc-helper/docs/features/hooks.md`）：`PreToolUse`/`PostToolUse`/`PostToolUseFailure`/`PermissionRequest`/`SessionEnd`/`StopFailure`/`PostCompact`/`Notification` 支持 matcher，`UserPromptSubmit`/`Stop` 不设 matcher，与 Claude 事件表一致；`*`/`""`/`".*"` 都表示匹配全部。
