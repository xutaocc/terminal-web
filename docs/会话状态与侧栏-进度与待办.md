## 已完成

### 1. PC 端项目分组侧栏

- 三级结构：文件夹 → 目录卡片（同一工作目录的会话合为一张）→ 会话 chip（最初是按路径自动归组的"项目"，已改为文件夹显式归属，见 1b）。
- 侧栏收起或在手机上时，顶部标签栏显示全部会话。
- 侧栏收起 / 拖拽调宽（200–500px，双击恢复）、项目组折叠、底部工具栏（设置、帮助、定位当前会话、收起）。
- 代码：`web/project-sidebar.ts`、`web/project-groups.ts`、`src/projects.ts`；`/api/sessions` 返回会话 `cwd`。

### 1b. 侧栏改为"文件夹显式归属"（原待办 B2，2026-10-16 完成并上线）

- 大文件夹只是分组容器，只有名字，和路径无关；会话归属由用户决定（新建时所在文件夹、拖拽 chip 或整张卡片、右键"移到「X」/移出文件夹"），`cd` 不会换组。
- 文件夹不能直接删除，组头只有"重命名"和"在此新建会话"。最后一个会话离开时文件夹随之删除：本设备关闭时确认框内提示；拖出/移出时先确认；别处关闭或进程退出时自动删除并提示"已无会话，已删除"。
- 新建文件夹必须同时新建第一个会话，取消则都不建。
- 文件夹内按工作目录合并为目录卡片（子文件夹）。卡片可重命名（只改显示名，按文件夹分别记，改回原名即恢复默认）；整张卡片可拖到别的文件夹，目标已有相同目录时自动合并，名称以目标为准。
- 同一目录可以出现在不同文件夹；没有归属的会话在最后的"未分组"（灰色小字）；一个文件夹都没有时直接平铺。
- 顶部标签栏只显示当前文件夹里与当前会话同一目录的会话（按建议选了这一种，可改为显示当前文件夹全部会话）。
- 存储：`~/.terminal-web/projects.json`（文件名沿用），结构 `{ folders, members, dirNames }`；旧的路径式项目在首次读取时迁移为同名文件夹并立即写回。迁移前的原文件备份为 `projects.json.bak-before-folders`。
- 接口 `/api/folders`：`create` / `rename` / `move`（可带 `card` 携带卡片名）/ `renameDir`，不提供删除。会话列表接口每次刷新时清理已不存在会话的归属。
- 代码：`src/projects.ts`、`web/project-groups.ts`（`groupByFolder`、`wouldEmpty`）、`web/project-sidebar.ts`、`web/terminal.ts`；测试 `tests/project-groups.test.ts`。

### 2. 会话状态显示

- 状态由服务端统一判断（`src/agent-status.ts`），通过 SSE 推给浏览器，所有设备一致，没打开过的标签也有状态。
- 五种状态，标签、侧栏、手机端共用：等待确认（橙色闪烁）、执行中（转圈）、完成未读（亮绿 + 标签淡橙底）、完成已读（暗绿）、空闲（灰）。
- 正在看的会话自动已读（页面可见且有焦点、标签在屏幕上）；页面标题前显示需要处理的会话数。
- 状态来源三选一，在设置面板"状态来源"切换，立即生效、各设备共用（存 `~/.terminal-web/agent-status.json`）：
  - **钩子**（默认）：agent 通过钩子主动上报；没上报过的会话用屏幕识别兜底。
  - **屏幕识别**：服务端每秒读 tmux 屏幕，按各 agent 的精确字样判断。
  - **原始**：原来的浏览器端逻辑，代码原样保留。
- 钩子接口 `/api/agent-hook`，钩子脚本 `scripts/agent-hook.sh`，一键安装 `scripts/install-agent-hooks.mjs`（`--check` / `--uninstall` / `--only` / `--url` / `--claude-dir`）。
- 一键安装支持 Claude Code（自动识别 `~/.claude`、`$CLAUDE_CONFIG_DIR`、`~/.claude-*`）和 Codex（`hooks.json` + `config.toml` 信任条目）。
- 屏幕识别规则覆盖：Claude Code、Codex、qwen-code、Kimi Code、opencode、MiMo Code（字样对照表见部署指南第 7 节）。
- 本机已安装钩子：`~/.claude`、`~/.claude-relay`、`~/.codex`，原文件备份为 `*.bak-terminal-web`。
- 测试：`tests/agent-status.test.ts`、`tests/project-groups.test.ts`。

## 待办

### A. 其他 agent 接入一键安装钩子

格式已从各自源码查清，尚未实现。接入后部署指南第 7 节"安装钩子"和"交给 AI agent 自动安装"两段要同步更新。

| Agent | 方式 | 要点 |
| --- | --- | --- |
| qwen-code | 配置式，和 Claude 相同 | `~/.qwen/settings.json`（`$QWEN_HOME` 可改）的 `hooks`；事件名与 Claude 一致；默认开启，用户级钩子无需信任；脚本输出 `{}` 或不输出均可。可直接复用 `agent-hook.sh` |
| Kimi Code | 配置式 | `~/.kimi-code/config.toml`（`$KIMI_CODE_HOME` 可改）的 `[[hooks]]` 表，键 `event` / `command` / `timeout`，**不要写 `matcher`**（Kimi 当正则解析，`*` 非法）；事件 `UserPromptSubmit`、`PreToolUse`、`PostToolUse`、`PostToolUseFailure`、`PermissionRequest`、`Stop`、`StopFailure`。已有 Orca 的条目可参照 |
| opencode | 插件 | 新版已去掉配置里的命令钩子。在 `~/.config/opencode/plugins/*.ts` 放插件，订阅 `session.status`（`status.type` 为 busy/idle）、`session.idle`、`permission.asked`；插件运行在 TUI 进程内，能读到 `TMUX_PANE` |
| MiMo Code | 插件，同 opencode | opencode 分支；目录 `~/.config/mimocode/`（`$MIMOCODE_HOME` 可改）下 `hooks/` 或 `plugins/`；事件名需装上后核对 |

建议顺序：先做 qwen-code 和 Kimi（配置式、风险低），opencode 和 MiMo Code 等实际安装后再做。

### C. 可选改进（暂不做）

- 普通 shell 长命令（`npm run dev`、编译）在屏幕识别下显示执行中：前台进程不是 shell 且屏幕持续变化即算执行中。当前决定保持严格，不做。
- 服务重启后未读状态会清空：可将未读持久化到文件。
- 完成 / 等待确认时发浏览器系统通知：需要 https 访问（http 页面浏览器不允许弹通知），目前只在页面标题显示数字。
- 侧栏目录卡片会话很多时可折叠为摘要条（参考 Orca）。
- 侧栏子目录是否合并到同一卡片（目前按完整路径区分）。
