# Web Terminal 部署与使用指南

适用于 Ubuntu Linux、已有的 Windows WSL Linux 环境，以及 macOS。**原生 Windows 环境暂不可用**，Windows 用户需要在已有 WSL 环境中运行服务端。浏览器客户端可以使用 Windows、macOS 或手机等设备。

本文对应包含共享 Token 认证功能的 `xt-dev261011-f-main` 分支。

## 1. 环境依赖

启动前需要准备：

- **Node.js 和 npm**：建议使用 Node.js 22。已有其他版本可以先尝试安装和运行；若遇到依赖安装或兼容性报错，再尝试 Node.js 22。项目声明最低版本为 Node.js 18。
- **tmux**：必需，用于终端会话、断线恢复和历史滚动。macOS 建议使用 **3.8**，Ubuntu Linux（含 WSL Ubuntu）建议使用 **3.4**。这些是建议版本，不是强制要求；已有其他版本且能正常使用时直接复用，不重复安装。
- **Git**：用于获取和更新项目，优先使用系统已有环境。
- **Python 3**：安装 node-pty 原生依赖时可能需要，优先使用系统已有环境。
- **编译工具**：安装 node-pty 原生依赖时可能需要。

请先确认已有 Git 和 Python 3 可用，无需重复安装或另装不同版本。本文不提供它们的安装步骤。

Tailscale、EasyTier 和 tmux 恢复插件均为可选依赖，普通局域网使用无需安装。

先检查 tmux 是否可用：

```bash
command -v tmux
tmux -V
```

检查成功即可复用现有 tmux，跳过下面的 tmux 安装步骤。自定义目录中的 tmux 也可以复用，只需确保服务的 PATH 能找到它；无需为了本项目另装一份。

### tmux 版本建议与复用原则

| 部署环境 | 建议版本 |
| --- | --- |
| macOS | tmux 3.8 |
| Ubuntu Linux / WSL Ubuntu | tmux 3.4 |

以上版本供新环境准备和兼容性排查时参考，不代表其他版本不能使用：

- **已有 tmux**：先使用现有版本部署和运行。运行正常时，无需重新安装、升级或降级到建议版本。
- **尚未安装 tmux**：再按下方步骤安装。包管理器提供的版本可能与建议版本不同，可以先尝试运行，不要求为对齐版本而额外安装一份。
- **出现 bug 时**：先记录 `tmux -V` 和 `command -v tmux` 的结果，检查服务 PATH、tmux 配置及相关日志；若仍怀疑版本兼容性，再考虑使用对应系统的建议版本复现和排查。

### Ubuntu / WSL Linux

仅在缺少 tmux 时执行以下命令，适用于 Ubuntu、Debian 及 WSL 中的 Ubuntu：

```bash
sudo apt update
sudo apt install -y tmux
```

编译工具也优先复用已有环境；仅在安装原生依赖时提示缺少编译工具，才补充：

```bash
sudo apt install -y build-essential
```

其他 Linux 发行版同样先检查已有依赖，仅在缺失时通过相应包管理器安装。

### macOS

仅在缺少 tmux 且已安装 Homebrew 时：

```bash
brew install tmux
```

如果安装依赖时需要编译工具，且系统中尚未提供：

```bash
xcode-select --install
```

Node.js 和 npm 请按自己的常用方式准备，不要求特定版本管理工具。安装后检查：

```bash
node --version
npm --version
tmux -V
git --version
python3 --version
```

## 2. 获取代码与安装

在 Linux 或 macOS 终端中执行：

```bash
git clone --branch xt-dev261011-f-main https://github.com/xutaocc/terminal-web.git
cd terminal-web
npm ci
npm run build
```

已有项目则进入实际目录，无需重新克隆。不要跨系统复制 `node_modules`，应在目标系统重新安装。

安装时保留开发依赖，不要使用 `--omit=dev`：当前启动需要 tsx，构建需要 esbuild。

## 3. 配置与启动

首次配置时复制模板，已有 `.env` 则直接编辑，避免覆盖：

```bash
cp .env.example .env
```

局域网使用可在 `.env` 中设置：

```dotenv
HOST=0.0.0.0
PORT=8090
DEFAULT_SESSION=web
```

`0.0.0.0` 表示监听所有 IPv4 网卡；仅供本机使用可改为 `127.0.0.1`。浏览器访问时使用服务器实际 IP，不使用 `0.0.0.0`。

启动：

```bash
bash scripts/start.sh
```

脚本自动加载 `.env`，启动后打印 Token 和各网卡对应的带 Token 访问链接。未监听的地址会标注说明。

也可以直接指定配置启动：

```bash
HOST=0.0.0.0 PORT=8090 npm start
```

注意：`npm start` 本身不会自动加载 `.env`。前台运行使用 `Ctrl+C` 停止。

## 4. 登录与使用

打开普通地址，在 Web Terminal 登录页输入 Token：

```text
http://SERVER_IP:8090/
```

或者使用启动日志打印的完整链接：

```text
http://SERVER_IP:8090/?token=YOUR_TOKEN
```

将示例中的 IP 和 Token 替换为实际值。链接登录成功后会自动移除地址中的 Token。

默认 Token 文件：

```text
~/.config/terminal-web/auth-token
```

首次启动生成，后续重启继续使用同一个 Token。可在服务器终端查看：

```bash
cat ~/.config/terminal-web/auth-token
```

可选的 `AUTH_TOKEN_FILE` 用于指定保存路径；非空 `AUTH_TOKEN` 环境变量优先覆盖文件中的 Token。正常使用无需设置它们。

使用规则：

- 所有页面、API、文件接口和终端连接均要求认证，包括局域网访问。
- 登录凭据保存在 HttpOnly Cookie 中，多个设备可同时登录，不会互踢。
- 服务端没有登录超时；浏览器清除 Cookie、保存期限结束或隐私窗口关闭后，可能需要重新登录。
- “退出登录”只退出当前浏览器及同源标签页，不影响其他设备，也不结束 tmux 中的任务。
- 关闭网页、断网后可以重新连接原会话；**关闭会话 `×` 或重启会话会终止其中的程序**。
- 多设备连接同名会话时共享同一个终端；可通过 `/?session=work` 指定会话。

## 5. 后台运行

先停止同端口的前台实例，再在项目目录安装服务：

```bash
HOST=0.0.0.0 PORT=8090 bash scripts/service.sh install
```

Linux 使用 systemd 用户服务，macOS 使用 launchd 用户服务。WSL 中使用此方式的前提是已有可用的 systemd。

常用操作：

```bash
bash scripts/service.sh status
bash scripts/service.sh logs
bash scripts/service.sh restart
bash scripts/service.sh uninstall
```

后台服务安装器不会加载 `.env`；HOST、PORT 等支持的配置应在安装命令中传入。其他配置需要调整生成的服务文件。修改 `.env` 不会自动改变后台服务。

后台服务的 PATH 与交互终端可能不同，特别是 macOS Homebrew 路径。前台正常、后台提示找不到 tmux 时，将 `command -v tmux` 对应目录加入服务配置的 PATH。

Linux 的开机启动取决于 systemd 用户服务及 linger 配置；macOS 用户服务通常在用户登录后启动；WSL 服务需要 WSL 实例保持运行。

## 6. 更新与重置 Token

更新前确认没有需要保留的未提交修改：

```bash
git pull --ff-only
npm ci
npm run build
bash scripts/service.sh restart
```

未安装后台服务时，最后一步改为重新执行 `bash scripts/start.sh`。

需要更换 Token 时：先停止服务，删除当前 Token 文件，再启动。新 Token 会自动生成，所有设备需要重新登录。如果设置了非空 `AUTH_TOKEN`，应更改该环境变量，而不是仅删除文件。

## 7. 注意事项与排查

| 问题 | 检查方向 |
| --- | --- |
| 无法创建终端 | 确认 tmux 已安装，并在服务 PATH 中 |
| 怀疑 tmux 版本兼容性导致异常 | 先检查现有版本、服务 PATH、配置和日志；排查后再考虑 macOS 使用 3.8、Ubuntu / WSL Ubuntu 使用 3.4。运行正常时无需更换现有版本 |
| npm 安装失败 | 检查编译工具、Python 3；已有其他 Node.js 版本可先尝试，遇到兼容性问题再使用 Node.js 22 |
| 端口已占用 | 停止重复实例，或修改 PORT |
| 本机可访问，其他设备不可访问 | 检查 HOST、真实 IP、防火墙及路由；WSL 还需确认网络转发或镜像网络配置 |
| 未登录返回 401 | 正常现象，输入 Token 或使用完整登录链接 |
| Token 文件为空或不可读取 | 检查服务用户、路径和权限；按重置流程处理 |

其他注意事项：

- 使用普通用户运行，避免 root。登录者能操作该服务用户有权限访问的终端和文件。
- 启动日志含完整 Token，不要公开日志、访问链接或截图。
- 默认 HTTP 不加密传输；需要加密时使用 HTTPS 代理，并正确转发 WebSocket、Host 和协议。
- Windows 用户应在 WSL Linux 内准备 Node.js、tmux 和项目依赖，并使用 Linux 内已有的 Git、Python 3，避免混用 Windows 环境。
- 服务重启通常不结束 tmux 任务；主机重启或关闭 WSL 会结束运行中的进程。可选恢复插件不能完整恢复进程内存状态。
- 上传文件默认保存在 `~/terminal-web-uploads`；下载接口可以读取服务用户有权限读取的普通文件。
