# 会话状态与 token 同步设计

分支：`fit-status-f-share-multi-platform-261027`。

## 原实现与截图含义

- 会话运行状态来自 AgentStatusMonitor，支持 hooks、屏幕识别和 legacy 输出推断；SSE 分发本机及远程状态。
- 未读事件有 instance/version/eventSeq，但浏览器用 localStorage 保存读取游标。管理员与分享页仅在本地存储命名空间上分离，同 token 跨设备不共享读取进度。旧 `/api/agent-status/read` 实际不更新状态。
- 圆圈转动代表执行中；带点蓝色勾代表完成未读；灰色实心点代表完成已读；空心圈代表空闲；问号代表等待确认。
- 额外 has-unread 伪元素会叠加到转圈上。历史 fallback 渲染和聚合进一步增加混合状态的理解成本。
- 黄色底线代表访问历史，不代表未读。旧底线最多取 10 个最近项，顶部“最近访问 N”另有列表、容量、本地删除记录及设备偏好，因而可出现 N=2 却高亮很多项。
- 蓝色角框代表当前选中的会话，与执行和已读无关。

## 新模型

运行事实和用户阅读状态分层：运行事实仍由服务器检测，所有有权限的 token 看到相同事实；用户的读取进度、最近访问列表与容量由 token 独立持有。

| 状态 | 展示 | 是否进入待读入口 |
| --- | --- | --- |
| waiting | 问号，等待确认 | 是，阅读不等于确认操作 |
| working | 单独转圈，隐藏旧未读装饰 | 否 |
| done + eventSeq > readSeq | 带点蓝勾 | 是 |
| done + eventSeq <= readSeq | 灰色实心点 | 否 |
| idle | 空心圈；如有尚未读的事件仍提示待读 | 按事件游标 |

每个图标只采用一个状态类。聚合目录、分屏仍使用 waiting > working > unread > done > idle 的优先级。

黄色底线、最近访问菜单与循环切换使用同一份列表。同 token 的 PC 与手机共享列表、删除操作和容量。顶部数字表示容量上限，不是当前已有条目数。普通点击更新访问顺序；循环切换不改顺序，避免绕圈目标跳动。当前选择、终端分屏、字体等设备布局仍保留原有行为。

## 同步与隔离

- 新增 `/api/viewer-state`，由服务端认证边界决定 scope，不接受客户端指定 token/scope。
- 管理员 scope 使用管理员 token 的 SHA-256 摘要；分享 scope 使用分享 ID 和 token 摘要。分享 token 重置后使用全新状态空间。
- 分享路由只允许读写授权会话；远程会话采用 `@host/session` 键，在当前入口服务器保存读取状态，不借用远端管理员的用户状态。
- 已读键为 `[会话键, instance]`；确认只推进已观察到的 eventSeq，使用 max 合并。旧请求不倒退游标，不会读掉稍后到达的新事件。
- `viewer-state.json` 原子写入并串行处理操作，支持 `VIEWER_STATE_FILE` 配置。先持久化再广播。
- 现有 SSE 增加 viewer-state 通知；客户端拉取完整状态，通过 revision 拒绝旧响应。重连、页面恢复、15 秒补偿刷新修复漏通知；请求超时后保留当前页面的待提交操作并重试。
- 读确认要求：页面可见、桌面窗口有焦点、会话正在显示、没有文件/设置/分享浮层遮挡、终端已连接且渲染过输出。

## 升级边界

不把旧浏览器本地阅读记录和访问历史自动合并进新 token 状态，避免无法证明归属的历史污染。首次启用列表为空，容量默认 8，之后服务端持久化。同 token 的新浏览器直接恢复服务端数据。

本次重写阅读/访问状态持久化、同步和呈现协调层；保留已有 hooks/屏幕/legacy 检测器。屏幕推断本身仍有误判可能，legacy 完成仍按原有静默超时判断。检测器重启/切换模式会产生新的运行 instance，重新识别的完成事件可能需要重新阅读。未成功提交的离线操作仅在当前页面内保留，关闭页面会丢失；不会把未提交的读取冒充成已持久化结果。

旧读取接口为兼容老页面保留空响应，跨设备同步要求使用升级后的前端。部署需重启服务并刷新各设备页面。

## 验证

- TypeScript 类型检查、前端构建。
- 单元测试覆盖同 token PC/手机同步、不同 token 隔离、并发游标合并、断网重试、后到事件不被旧读取清除、实例替换、访问列表操作、文件持久化及权限过滤。
- 浏览器验证执行中转圈、完成未读、管理员读取后分享仍未读，以及同 token 移动页面读取服务端进度。
- 分享集成测试新增管理员/分享/远程状态断言通过；原有后续操作权移交测试在 handover request 步骤超时，完整套件未通过。在独立目录构建并运行原始 HEAD 后，同一步骤也出现 handover request 超时，已确认基线同样存在该失败。

## 分享首次纳入会话的基线（2026-10-27）

新建分享、添加会话和重置 token 时，服务器以当前状态事件序号建立一次性读取基线。基线按分享 token、会话键和持久会话身份保存，不按浏览器或设备保存。因此创建分享前的完成结果不会制造待读，创建后的新事件仍正常提示；等待确认仍使用问号。

同 token 刷新、重新连接、换设备及检测器运行 instance 变化都不重新建立基线。旧分享已有读取记录时保留原进度；没有记录的会话首次取得状态时初始化。远程离线且没有缓存时延迟到首次取得有效状态，这之前的事件将计入初始基线。

分享 SSE 在发送运行状态前发送同 token 的可见阅读快照，避免基线请求与运行状态到达顺序不同而短暂出现历史待读。快照仍按分享授权会话过滤。

分享设置显示只读的“状态来源：… · 跟随当前主机，由管理员设置”，随当前设置对象切换；管理员保留原切换按钮。

## 分享文件操作权限

分享管理新增“文件操作”开关（开/关），默认关闭，旧分享也保持关闭。关闭时仍可浏览、预览和下载；开启后可在授权根目录内新建、编辑、上传、重命名、复制、移动、删除、统计、压缩及修改系统支持的文件权限。开关独立于终端操作权，不会因切换而断开终端。

已打开的文件管理器通过 SSE 实时更新，网络失联时先退回只读。服务器每次请求检查最新权限，上传分块和后台任务也检查授权；关闭不会回滚已经完成的文件操作。文件任务和压缩计划绑定分享 token、会话身份及根目录，不能借用其他分享的任务 ID。

所有路径同时校验授权根目录及真实路径。不得删除、重命名或移动授权根目录；不能通过父路径、符号链接越界，写操作拒绝链接文件（含硬链接）和链接目录。压缩产物也必须留在根目录内。创建额外终端不属于此文件权限，仍不开放。

远程主机也需要升级本版本，使用带范围限制的文件代理及最新权限策略；旧版本远程收到修改请求时会明确提示升级，不降级转发到不受限的管理员接口。
